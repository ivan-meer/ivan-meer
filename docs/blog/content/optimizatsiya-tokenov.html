Каждый токен — это деньги. В AI-системах токены — это не просто ресурс, это прямые деньги. Оптимизация токенов — это не экономия на мелочах, это стратегия.

Проблема

Когда я вижу систему, которая тратит 100 токенов на простой вопрос, я понимаю: здесь есть куда копать.

Факт

В AdminHero токены на RAG-систему ушли с 30% до 10% бюджета после оптимизации.

Где же копать?

1. Prompt caching — первый и самый простой шаг

Prompt caching — это когда вы кешируете промпты и не отправляете их каждый раз на сервер. Это самый быстрый способ сэкономить токены.

# Настройка кэширования в Anthropic API
client = Anthropic(
    api_key=os.getenv("ANTHROPIC_API_KEY"),
    default_headers={
        "anthropic-beta": "prompt-caching-2024-07-31"
    }
)

# Использование кэшированных промптов
response = client.messages.create(
    model="claude-3-5-sonnet-20240620",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": SYSTEM_PROMPT,
            "cache_control": {"type": "ephemeral"}
        }
    ],
    messages=[
        {
            "role": "user",
            "content": user_query
        }
    ]
)

2. Сжатие контекста — когда история не нужна

История диалога — это не память, это шум. В 90% случаев вам не нужна вся история, вам нужен контекст.

def compress_history(history, max_tokens=8000):
    """Сжимает историю до ключевых фактов."""
    key_events = [
        msg for msg in history
        if msg.get("role") == "user" or
           msg.get("role") == "assistant" and
           msg.get("content").startswith("FACT:")
    ]

    if token_count(key_events) > max_tokens:
        return summarize_history(key_events)
    return key_events
Паттерн

В AdminHero мы используем семантическое сжатие: сохраняем только ключевые события и факты, а остальное суммаризируем.

3. Роутинг между моделями — когда не нужна мощь

Не все задачи требуют мощных моделей. Многие задачи можно решить на Haiku или Sonnet.

def route_to_model(task_type):
    """Выбирает модель в зависимости от типа задачи."""
    if task_type in ["chat", "generate", "simple_analysis"]:
        return "claude-3-haiku-20240307"
    elif task_type in ["coding", "complex_analysis"]:
        return "claude-3-5-sonnet-20240620"
    else:
        return "claude-3-opus-20240229"

4. Файнтюнинг vs few-shot — когда окупается

Файнтюнинг — это когда вы обучаете модель на ваших данных. Few-shot — это когда вы даёте модели примеры.

3×
эффективнее few-shot для сложных задач
10×
эффективнее few-shot для простых задач

Правило: если задача повторяется больше 5 раз — файнтюнинг. Если меньше — few-shot.

5. Мульти-шаговые пайплайны — когда нужно меньше токенов

Один большой запрос — это не всегда оптимально. Иногда лучше разбить задачу на несколько шагов.

def analyze_code(code):
    """Анализирует код в несколько шагов."""
    # Шаг 1: Извлечение структуры
    structure = extract_structure(code)

    # Шаг 2: Анализ сложности
    complexity = analyze_complexity(structure)

    # Шаг 3: Проверка на антипаттерны
    antipatterns = check_antipatterns(structure)

    return {
        "structure": structure,
        "complexity": complexity,
        "antipatterns": antipatterns
    }
Экономия

В AdminHero мульти-шаговые пайплайны сэкономили 25% токенов на анализе кода.

Грамли, на которые я наступил

1. «Модели всё понимают — давайте просто давать больше контекста»

Контекст — это не память. Модель не может понять всё, что вы ей даёте. Чем больше контекста, тем больше шум.

Решение: сжимайте контекст до ключевых фактов.

2. «Файнтюнинг — это дорого, давайте обойдёмся few-shot»

Файнтюнинг — это инвестиция. Если задача повторяется больше 5 раз — файнтюнинг окупается.

Решение: анализируйте частоту задач перед выбором подхода.

3. «Один запрос — это всегда лучше»

Иногда один большой запрос — это не оптимально. Иногда лучше разбить задачу на несколько шагов.

Решение: тестируйте разные подходы и выбирайте лучший.

Выводы

  1. Токены — это деньги. Оптимизация токенов — это стратегия.
  2. Prompt caching — первый и самый простой шаг. Начните с него.
  3. Сжимайте контекст. Модель не может понять всё, что вы ей даёте.
  4. Выбирайте модели в зависимости от задачи. Не все задачи требуют мощных моделей.
  5. Файнтюнинг — это инвестиция. Если задача повторяется больше 5 раз — файнтюнинг окупается.
  6. Разбивайте сложные задачи на шаги. Иногда один большой запрос — это не оптимально.

Готовый сценарий: берёте prompt caching, добавляете сжатие контекста, навешиваете роутинг между моделями и мульти-шаговые пайплайны сверху. Это — база. На этой базе можно строить систему, которая экономит токены.
